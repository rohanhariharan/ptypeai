What it is

Three parts that fit together.

The device

A small square you talk to

An 86 mm handheld with a rainbow mark and Pip, the little fire that lives on it. Glanceable project cards and a push-to-talk button — no keyboard, no screen full of apps.

The box

A local engine that does the work

A zero-dependency server holding a project ledger, an LLM agent with real tools, real git history, and Whisper voice — with an MCP endpoint so other agents can drive it.

The console

A terminal cockpit

A full-screen TUI to run the whole thing: projects, requests, providers, models, MCPs and a live change timeline. Everything local; the only dependency is the model you pick.

Talk to it

A spoken thought becomes scheduled work.

Hold the button, say the thing. ptype transcribes it on your machine and files it into the project you’re on. Pip answers out loud, too — a real conversation, not a form.

“Hey Pip, add a landing page to my portfolio.”
→ filed to Portfolio
ptype — talk
you break my Kindle idea into steps
→ created a request “Pick a quote source”
→ created a request “Build the daily fetch script”
→ started “Pick a quote source” — an agent is on it
pip Set it up and the first step’s done.

The console

One ledger, four ways in.

Voice the thought, ask in the talk tab, type a request, or let another agent drive it over MCP. Every path lands in the same local ledger — and every change shows up on the timeline.

The agent

Tell it to do something. It gets done.

Press enter on a task and the model drives real tools inside a workspace on your disk: it writes files, reads them back, runs allowlisted commands, and a tester must pass before the task is done. Then it commits to git — real history, not a claim.

fetch.js · written 612 B
$ node fetch.js ok
tester passed
committed 3f864e4
