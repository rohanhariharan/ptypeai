For agents

The engine on the machine is also the API. A local HTTP service, an MCP server and a task ledger, so another agent can file work, run it and read the result instead of describing it.

Endpoint

Engine     http://localhost:8787
Health     GET /api/health
MCP        POST http://localhost:8787/mcp   (alias /api/mcp)
Protocol   MCP JSON-RPC 2.0, 2024-11-05
Data       ~/ptype/ptype.db and ~/ptype/<project-slug>/
Auth       none. CORS: *

Capture the mcp-session-id response header from initialize and send it on every later call. The service listens on loopback only and trusts anything that reaches it, so keep port 8787 off the network.

MCP client

Point any MCP client at the endpoint. The common shape:

{
  "mcpServers": {
    "ptype": { "url": "http://localhost:8787/mcp" }
  }
}

From Claude Code, the same thing as one command:

claude mcp add --transport http ptype http://localhost:8787/mcp

Workspace rules

  • A workspace lives at ~/ptype/<project-slug>/.
  • A request needs a result_path, and it is separate from the workspace.
  • The agent is confined to the workspace. Absolute paths and .. are rejected.
  • run takes one allowlisted program and its arguments. No shell operators, and a twenty second timeout.
  • Allowed programs: node, python3, pwd, ls, cat, head, tail, wc, grep, echo, mkdir, touch, git, sort, uniq, find, printf, sed, awk, true.
  • The Python gate is python3 -m compileall -q . and pytest -q when a tests folder exists. The JavaScript gate is node --check. Language server errors also reject.
  • Only a passing request is committed and copied to the result path.
  • A worker gets twelve steps an attempt, three attempts, twenty history entries and a 180 second model timeout. Talk gets twelve steps. Research gets twenty four, with a ten step search budget.

The worker names its tools in JSON:

write_files, write_file, read_file, list_dir, run, web_search,
diagnostics, definition, references, symbols, hover, remember, test, finish

Research mode

Set the reply mode to research when the answer needs sources. Tools are academic_search, web_search, search_workspace, read_file, list_dir and research_write.

  • Tools that change the project are blocked, and so is finish.
  • research_write is the only deliverable. It writes one markdown report and appends a Sources section from the sources array.
  • DOIs are resolved through Crossref and OpenAlex, so author, year and journal metadata come from the record rather than the model.
  • The default path is ~/ptype/research/<slug>-YYYY-MM-DD-HHMM.md. An output path may be a markdown file or a folder under home.
  • academicOnly filters the Sources section to DOI, arXiv, PubMed, .edu, .ac and known scholarly publishers. Everything else is dropped and counted.

Memory

  • Scopes are global, project and agent.
  • Files live in ~/ptype/memory/{global,projects/<id>,agents/<agent>}/*.md.
  • Levels are nobot for read, subbot for read, write and create, and superbot for delete as well. The default is subbot.
  • There is no per-session todo. Use ledger tasks or project requests instead.

Safety

  • No authentication, and CORS allows any origin. Do not expose port 8787.
  • A remote model provider receives prompts, tool results and file excerpts. A workspace may contain secrets, and the worker can read it.
  • Tachyon can start opencode or Claude Code with auto-approve flags, which removes the confirmation step.
  • web_search and academic_search are the only designated network tools. Queries leave the machine.

Minimal loop

  1. GET /api/health
  2. GET /api/models
  3. Find or create a project.
  4. Create a request with a result_path.
  5. Start a run with POST /api/runs or run_task.
  6. Read the thread and the diffs.
  7. Report evidence, not claims.
